# Log Triage

[![tests](https://github.com/LigiaZ/log-triage/actions/workflows/tests.yml/badge.svg)](https://github.com/LigiaZ/log-triage/actions/workflows/tests.yml)

**The first ten minutes of an incident investigation, automated.**

Point it at an application log and it answers the questions I ask at the start of every investigation:

- **What's actually failing?** Thousands of lines collapse into a handful of error *signatures*, with IDs, numbers, IPs and timestamps masked.
- **Since when, and is it real?** Errors are bucketed over time and spikes are flagged against a robust baseline (median + MAD), so a long outage can't drag the baseline up and hide itself.
- **What changed?** Deploys, rollbacks, restarts and config reloads just before the spike are surfaced, whatever their log level.
- **Where do I start?** The earliest *new* warning or error before the spike.

Pure Python standard library, no dependencies. The same file runs in a terminal and in the browser.

**▶ Try it live in your browser:** [zanchet.eu/projects/log-triage](https://www.zanchet.eu/projects/log-triage/). Python runs locally via Pyodide, so your logs never leave the tab.

## Usage

```bash
python triage.py app.log                   # human-readable report
python triage.py app.log --window 300      # 5-minute buckets
python triage.py app.log --json            # full report as JSON
kubectl logs deploy/api | python triage.py -
```

Requires Python 3.9+.

### Supported formats

Plain text:

```text
2026-03-14T10:15:02.120Z ERROR [payments-svc] DB connection pool exhausted
2026-03-14 10:15:02,120 [WARNING] checkout-svc: Slow query took 1200ms
```

JSON lines, with common field names (`@timestamp`/`timestamp`/`time`, `level`/`severity`/`log.level`, `service`/`service.name`/`app`, `message`/`msg`):

```json
{"@timestamp": "2026-05-03T00:00:02Z", "level": "error", "service": "auth-svc", "message": "certificate has expired"}
```

Lines that can't be parsed are counted and skipped, not crashed on.

## How it works

| Step | What happens |
|---|---|
| Parse | Regex for text lines, `json.loads` for JSON lines; timestamps normalised to UTC |
| Normalise | Variable parts masked (`<uuid>`, `<ip>`, `<n>`, `<ts>`, …) to form signatures |
| Detect | Error counts per bucket; buckets above `median + max(3 × 1.4826 × MAD, 3)` are spikes; nearby spikes merge into one incident |
| Explain | Per incident: top signatures in the window, changes in the 15 minutes before, earliest new signature, and a plain-English summary |

## Samples and tests

`samples/` holds two synthetic logs with planted incidents, regenerated by `make_samples.py`:

- `checkout-outage.log`: a payments deploy leaks DB connections and checkout fails
- `auth-cert-expiry.jsonl`: an identity-provider certificate expires at midnight and logins fail

```bash
python -m unittest -v test_triage.py
```

The tests cover parsing, normalisation and spike detection, and check end to end that the triage points at the right cause in both samples.
